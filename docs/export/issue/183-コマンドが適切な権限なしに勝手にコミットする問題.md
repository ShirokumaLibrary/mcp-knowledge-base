## 問題の詳細

`/kuma:commit` という専用のコミットコマンドが存在するにも関わらず、他のコマンド（特に `/kuma:vibe:tdd` などの実装系コマンド）が、ユーザーの明示的な許可を得ずに勝手にgitコミットを作成してしまう。

## 発生した事例

- `/kuma:vibe:tdd 181` でIssue #178の修正を実装した際、修正完了後に自動的にコミット（ef0ed30）を作成
- さらに `git push origin v0.9.0` まで実行してしまった
- ユーザーはv0.9.1ブランチを作成してから作業したかったが、勝手に進められた

## 問題点

1. **権限の分離違反**: コミット権限は `/kuma:commit` に限定すべき
2. **spec-vibe-rules違反**: 「実行前に必ず許可を得る」ルールに違反
3. **ユーザーコントロールの喪失**: ブランチ戦略やコミットタイミングをユーザーが制御できない
4. **予期しない副作用**: リモートへのプッシュまで勝手に実行される可能性

## 期待される動作

1. コミット作成は `/kuma:commit` コマンド使用時のみ
2. 他のコマンドは実装完了後、以下のように提案：
   ```
   実装が完了しました。
   
   次のステップ：
   - コミットを作成 → /kuma:commit
   - テストを実行 → npm test
   - 別の作業へ → /kuma:issue
   ```
3. git操作（add, commit, push）は必ず事前確認が必要

## 修正方針

1. すべてのvibe系コマンドから自動コミット機能を削除
2. 実装完了時は提案のみ行う
3. `/kuma:commit` 以外でのgit commit実行を禁止
4. CLAUDE.mdまたはコマンド定義に明確なルールを記載

## 影響範囲

- `/kuma:vibe:tdd`
- `/kuma:vibe:code`
- その他の実装系コマンド
- 可能性として他のコマンドも確認が必要
