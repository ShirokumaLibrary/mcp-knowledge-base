## 改善要望の詳細

`/kuma:issue` コマンドでイシューを登録する際に、現在はユーザーの入力をそのまま登録しているが、より価値のあるイシュー登録にするため、以下の機能を追加する。

### 現状の問題点
- イシュー登録時にコードの現状を確認していない
- 関連する既存コードや設定を調査せずに登録している
- より具体的な問題定義や提案ができる余地がある

### 提案する改善内容

#### 1. イシュー登録前の自動確認
- **関連ファイルの特定**: イシューの内容から関連しそうなファイルを自動検索
- **現状分析**: 該当コードの現在の実装状況を確認
- **既存イシューとの関連性チェック**: 類似または関連するイシューの検出

#### 2. インテリジェントな提案機能
- **問題の具体化**: 曖昧な問題記述を、コード確認に基づいて具体化
- **影響範囲の特定**: 変更が影響する可能性のある箇所を事前に特定
- **優先度の提案**: コードの重要度や影響範囲から優先度を提案

#### 3. 確認プロンプトの強化
イシュー登録前に以下を確認：
```
## イシュー登録前の確認

### 📋 関連するコードの状況:
- 対象ファイル: [自動検出されたファイル]
- 現在の実装: [簡潔な説明]

### 🔍 関連する既存イシュー:
- #XXX: [関連イシューのタイトル]

### 💡 提案:
- より具体的なタイトル案: [提案]
- 推奨される優先度: [HIGH/MEDIUM/LOW]
- 追加すべきタグ: [提案]

この内容でイシューを登録しますか？ (yes/no/modify)
```

### 実装例

```bash
# ユーザー入力
/kuma:issue "エクスポート機能が動かない"

# AIの動作
1. "エクスポート"に関連するファイルを検索
2. export関連のコードを確認
3. 最近のエクスポート関連のイシューを検索
4. より具体的な問題定義を提案

# 出力
関連ファイルを確認しました:
- src/services/export.ts (エクスポート処理の実装)
- 最近の変更: フロントマター生成部分に非同期処理追加

関連イシュー:
- #178: 自動エクスポート時にフロントマターの一部が出力されない問題

提案:
- タイトル: "手動エクスポートコマンドでエラーが発生する問題"
- 優先度: HIGH (コア機能に影響)
- タグ: ["bug", "export", "critical"]

この内容で登録しますか？
```

### 利点
1. **より正確なイシュー登録**: コンテキストを理解した上での登録
2. **重複の削減**: 既存イシューとの関連性を事前確認
3. **開発効率の向上**: 問題の具体化により解決が迅速化
4. **知識の蓄積**: 関連性の自動検出により知識グラフが充実

### 実装上の考慮事項
- パフォーマンス: コード確認に時間がかかりすぎないよう制限
- オプション化: `--quick` フラグで従来の即座登録も可能に
- プライバシー: コード確認は必要最小限に留める
